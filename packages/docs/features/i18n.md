# 🌐 Internationalization

The KitchenAsty storefront supports multiple languages using [i18next](https://www.i18next.com/) with React.

## 🗺️ Supported Languages

| Code | Language |
|------|---------|
| `en` | 🇬🇧 English |
| `es` | 🇪🇸 Spanish |
| `fr` | 🇫🇷 French |
| `de` | 🇩🇪 German |
| `it` | 🇮🇹 Italian |
| `pt` | 🇵🇹 Portuguese |
| `pl` | 🇵🇱 Polish |
| `ru` | 🇷🇺 Russian |

## ⚙️ How It Works

- 📁 Storefront translations are stored in `packages/storefront/src/i18n/locales/`.
- 📁 Admin translations are stored in `packages/admin/src/i18n/locales/`.
- 💾 The selected language is persisted to `localStorage`
- 🏷️ The `<html lang>` attribute updates automatically on language change
- 🔄 Fallback language is English
- 🌐 The admin language picker is available in the authenticated shell, sign-in screen, and invite acceptance flow.

## 🔑 Translation Keys

Translations are organized by domain:

| Namespace | Content |
|-----------|---------|
| `common` | 🔗 Shared strings — loading, errors, buttons |
| `nav` | 🧭 Navigation items |
| `home` | 🏠 Homepage hero and features |
| `auth` | 🔐 Login and registration forms |
| `menu` | 🍽️ Menu browsing and search |
| `cart` | 🛒 Shopping cart |
| `checkout` | 💳 Checkout flow |
| `orders` | 📦 Order history and status |
| `reservations` | 🪑 Table booking |
| `reviews` | ⭐ Review submission and display |

## ➕ Adding a New Language

1. Create a new locale file:

```bash
cp packages/storefront/src/i18n/locales/en.json packages/storefront/src/i18n/locales/ja.json
```

2. Translate all keys in the new file.

3. Register the language in `packages/storefront/src/i18n/index.ts`:

```typescript
import ja from './locales/ja.json';

// Add to resources
resources: {
  // ... existing languages
  ja: { translation: ja },
}
```

4. Add the language option to the storefront language picker component.

## 🤖 Translation Script

For bulk translation, you can use automated tools:

```bash
# Example: translate en.json to Japanese using a translation API
npx tsx scripts/translate.ts --from en --to ja
```

## 🧩 Using Translations in Components

```tsx
import { useTranslation } from 'react-i18next';

function MenuPage() {
  const { t } = useTranslation();
  return <h1>{t('menu.title')}</h1>;
}
```

::: tip
The admin dashboard uses the same supported languages and English fallback. Admin resources are grouped into `common`, `nav`, `roles`, `status`, `kitchen`, `a11y`, `messages`, and page-specific `pages.<page>` keys, with additional groups for labels used in filters, charts, and form options. Its language preference uses the same `language` localStorage key as the storefront.

When adding admin UI, add matching keys to all eight JSON files in `packages/admin/src/i18n/locales/`. Just like the storefront example above, import `useTranslation` from `react-i18next`, obtain `const { t } = useTranslation()` inside the component, and render strings with `t(...)`. Each component that renders translations should use the hook so it updates when the language changes. Keep translation keys, rather than translated labels, in module-level constants and translate them during rendering. Shared status and role helpers receive the component's `t` function.

Keep interpolation variables identical in every locale. Server-provided errors, names, and other external values should remain as supplied, with English fallback for unknown values.
:::
